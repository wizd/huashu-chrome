# 云端发布：让 maker.vcorp.ai 在你的浏览器里替你发视频、办事

这个分支（`my-dev`）的 vcorp-chrome 多了一条「云端通道」：配对之后，[maker.vcorp.ai](https://maker.vcorp.ai)（或你自建的 Opus Video Maker）的 AI 可以在**你自己的 Chrome** 里操作网页：把做好的视频发到你说的平台、查资料、填表。

- 没有预设的平台清单，也没有写死的发布脚本。要去哪个网站，AI 按任务自己申请，你点头才放行；页面上怎么点、怎么填，由 AI 看着页面现场操作。
- 用的是你平时登录着的账号、你自己的电脑和网络，网站看到的就是你本人在操作。
- 网站的 cookie 和密码**不离开你的电脑**，服务器和它的 AI 都拿不到。
- 它只能在你允许过的网站上、在它自己开的标签页里点点填填；你的其它页面它一个都看不到。
- 每个新任务都要你点「允许」，除非你打开了「自动允许新任务」。随时可以暂停、收回、断开。

不需要装 Node.js，不需要终端。

---

## 一、安装扩展（约 3 分钟）

支持 Chrome 116 以上，以及 Edge、Brave 等 Chromium 内核浏览器。

1. **下载**：打开 <https://github.com/wizd/huashu-chrome/tree/my-dev>，点绿色的 **Code → Download ZIP**。
   （会用 git 的话：`git clone -b my-dev https://github.com/wizd/huashu-chrome.git`）
2. **解压**到一个**不会被删的位置**，比如 `文档\vcorp-chrome`。浏览器每次启动都从这个文件夹读扩展，删了扩展就没了。
3. 在地址栏打开 `chrome://extensions`（Edge 是 `edge://extensions`），打开右上角的 **开发者模式**。
4. 点 **加载已解压的扩展程序**，选解压出来的文件夹里的 **`extension`** 子文件夹（里面有 `manifest.json` 的那个，不是外层文件夹）。
5. 点地址栏右边的拼图图标，把 **vcorp-chrome** 旁边的图钉点上，图标就固定在工具栏上了。

装好后会自动打开一个欢迎页，点里面的「打开侧栏」，或者直接点工具栏上的图标。

> 已经从 Chrome 应用商店装过上游的 huashu-chrome？两个版本的扩展 ID 一样，会互相顶掉。先在 `chrome://extensions` 里把商店版移除，再加载这个。本机 AI agent 那套功能（`npx vcorp-chrome install`）在这个版本里照常可用。

> Chrome 启动时可能提示「请停用以开发者模式运行的扩展程序」，点 **×** 关掉提示即可，不要点「停用」。

## 二、和网站配对（约 1 分钟）

1. 登录 maker.vcorp.ai，右上角菜单 → **浏览器扩展** → **获取配对码**，得到一个 `ABCD-EFGH` 样子的码（10 分钟内有效，只能用一次）。
2. 在扩展侧栏的 **云端发布** 里填这个码，点 **下一步**。
3. 侧栏会显示「要把这个浏览器交给 maker.vcorp.ai 上的账号『xxx』吗？」。**核对账号是不是你自己的**，再点 **确认连接**。
   配对码如果是别人发给你的，点取消——填别人的码，等于把你浏览器里的登录交给别人去用。
4. 网页上「已连接的浏览器」里会出现这台电脑，显示 **在线**。

## 三、允许的网站

侧栏「允许它使用的网站」一开始是空的，扩展里没有预设平台。任务要去哪个网站，会先用 `sites` 申请，你点 **允许** 之后，这个网站（含子域）就记进这份名单；以后的任务再用到它，不用再批网站，只批任务本身。名单里每一行都能点 **移除**，进行中的任务也立刻失去它。

要发布的平台，在这个浏览器里**正常登录它的创作者后台**就行，就像你平时手动发视频那样。登录状态就是你浏览器里的登录状态，不需要导出 cookie。

如果发布时发现没登录，扩展会把那个标签页切到前台、弹一个通知，请你扫码登录，登录完点浮条上的「我完成了」。

## 四、发布时会发生什么

1. 在网页上新建发布任务，写清发到哪里、怎么写，确认策划后开始发布。
2. AI 先申请要去的网站。没开「自动允许新任务」时，浏览器弹出通知「maker.vcorp.ai 请求在你的浏览器里操作这些网站 → creator.douyin.com、creator.xiaohongshu.com」，点 **允许**（也可以在侧栏里点）。5 分钟没点算拒绝。开了这个开关，这一下不再问。
3. 浏览器在**后台标签页**里操作，不会抢你正在看的页面。这些标签页带彩色边框，归在一个以「Cloud · maker.vcorp.ai」命名的标签组里，点开就能看它在做什么。
4. 发完，任务结束，它开的标签页自动关掉（你正在看的那一页除外）。

### 任务进行中再申请网站

做的过程中如果还要去别的网站（比如查资料、下素材），它会再发一条申请，浏览器弹出通知「maker.vcorp.ai 的任务还想访问新的网站」，侧栏里同一张任务卡片上也有「允许这些网站 / 不允许」。

- 每次只问这次新出现的网站，点头之后它的标签页才能停在这些站和它们的子域上，这些站也进允许名单。
- 「自动允许新任务」管不到这里，每个新网站都要你点头。同一个任务里你拒绝过的，不再问第二次。
- 已经在允许名单里的不用再批。允许过 `douyin.com`，再申请 `creator.douyin.com` 不会弹窗。
- 一个任务最多新批 20 个网站。

开了「自动允许」时，任务一开始带着的网站和任务一起放行，但只给这一个任务用，不进允许名单，任务结束就作废。之后每多一个网站再问一次。

### 读取你电脑上的文件夹

网页上「已连接的浏览器」里有「挂载本地文件夹」。点下去之后，扩展弹出一个小窗口（侧栏里的「添加文件夹」也是这个窗口），你自己选一个文件夹，并给它一个显示名。选文件夹这一下发生在扩展里，网页碰不到你的磁盘。

之后某个任务要读这个文件夹时，浏览器再弹一次通知「想读取你的本地文件夹 → 知识库」，侧栏的任务卡片上同样有允许 / 不允许。「自动允许」管不到这里。

- 只读。扩展不会改、不会删你的文件。
- 只读这些类型：Markdown、文本、PDF、Word（.docx）、CSV、JSON、HTML。隐藏文件、`node_modules`、私钥这类没有这些扩展名的文件不会被列出，也不会被传走。
- 单个文件最大 32MB，一个任务累计最多 256MB。
- 服务器只知道显示名，不知道 `D:\...` 这样的路径。
- 浏览器重启之后，读取权限可能会失效。侧栏或弹出的窗口里点「恢复访问」，再点一次允许即可，不用重新选文件夹。
- 移除挂载只是忘掉句柄，文件夹还在你的磁盘上。

全程 Chrome 要开着、电脑不能睡眠。

### 侧栏里的开关

| | |
|---|---|
| 自动允许新任务 | 不再逐个弹窗确认。只在你信任这个账号时打开：新任务，以及它一开始就要去的网站，会直接放行。任务开始之后再加的网站，还有本地文件夹，仍然要你逐个点头 |
| 暂停 | 立刻断开，云端的命令一条都不接，直到你再关掉 |
| 收回 | 结束某个进行中的任务，关掉它的标签页 |
| 操作记录 | 最近 200 条：批准、拒绝、每条命令和结果 |
| 断开并忘记这个服务器 | 删除本机密钥、所有任务和云端开的标签页；要再用得重新配对 |

在网页上「移除」一个浏览器，扩展也会自动解除配对。

### 常见问题

- **网页显示浏览器离线**：Chrome 没开，或侧栏里点了暂停，或电脑睡眠了。打开 Chrome 等几秒；还不行点侧栏的「重连」。
- **侧栏显示「服务器不认这个设备的签名」**：在网页上被移除过，或服务器换了地址。点「断开并忘记」后重新配对。
- **一直弹验证码 / 提示操作频繁**：平台在风控。在那个标签页里手动处理一次；频繁出现就暂停一段时间再发。
- **自建服务**：配对前在侧栏「服务器地址」里改成你自己的 https 地址。

## 五、安全设计（给想审一审的人）

### 威胁模型

这条通道的对面是公网上的服务器。设计前提是：**服务器可能被攻破**，攻破后下发的每条命令都是敌意的。所以安全不能靠「服务器不会乱发」，只能靠扩展自己拒绝。规矩集中在一个纯函数文件里，不依赖任何 chrome API，有单元测试：

- `extension/cloud-policy.js`：规矩本身
- `test/cloud-policy.test.js`：每条规矩对应的攻击
- `extension/cloud.js`：连接、配对、任务批准、标签页归属、上传

服务器端实现见 Opus Video Maker 的 `extlink.js`（不在本仓库）。每个任务的信封只有任务号、标题和 `sites`（这个任务申请过的域名）。agent 发 `sites` 命令申请网站，参数是 `add`（域名列表）和一行 `reason`。没开「自动允许」时，第一次申请连同任务一起问你；任务开始之后再申请的网站单独问。开了的话，新任务和信封上一开始带着的网站直接放行，之后再申请的仍然单独问。

### 服务器被攻破时，它**能**做什么

在你**已经批准**的任务里、**允许名单**里的网站上，以及这个任务获准的网站上，以你的身份在网页上操作：发帖、改资料、删帖。开了「自动允许」时，新任务和它一开始的网站清单也算批准。任务开始之后再申请的网站，每个都要你另外点头，点头之前页面打不开。这是这个功能本身的能力，没法去掉，只能收窄：

- 允许名单里只留你要用的网站，用不着的点移除；不用时暂停或断开。
- 不开「自动允许」，每个新任务都要你点头，先看一眼它要去的网站和用途。
- 开了「自动允许」，这些新任务不再问。任务开始之后再申请的网站，以及本地文件夹，仍然逐个点头。开关开着时，服务器可以在新任务的第一份网站清单里写最多 20 个域名，扩展不再问就放行（只给这个任务，不进允许名单）。不信任这个账号时不要开。
- 一个任务最多新批 20 个网站；IP、localhost、内网名，以及 `com.cn`、`github.io` 这类共享后缀一律申请不了。
- 每个任务最多 1500 条命令、每分钟最多 120 条；闲置 3 小时后批准作废。
- 提交/发布/删除/支付一类的按钮不能夹在批处理（`act`）里，必须单独点，每一下都进操作记录；支付按钮仍会弹原有的付款确认。

### 它**不能**做什么

| 攻击 | 拦在哪 |
|---|---|
| 执行任意 JS、读接口、带着 cookie 发请求、看网络记录、下载文件到你的磁盘 | `eval` `fetch` `network` `download` `reload` 不在云端命令白名单里，扩展直接拒绝 |
| 打开网银、邮箱、`chrome://`、`file://` 或任何没允许的网站 | 开页、导航、`act` 里的每个导航步骤都按「允许名单 + 本任务里放行的网站」核对，各含子域。允许过 `channels.weixin.qq.com` 不等于允许整个 `weixin.qq.com`，申请上一级域名仍要你单独点头 |
| 点个外链或重定向跳出允许的网站，再读页面内容 | 每条命令前、结果发回之前，都核对本任务所有标签页（含正在加载的地址）；跳出去了结果整份屏蔽，标签页退回或清空 |
| 看或操作你自己开着的标签页 | 云端只能碰它在本任务里开的页（以及从这些页里点开的新页）；参数里的 `tabId` 一律剥掉，以任务表为准 |
| 让本机 agent 误接管云端的页 | 云端开页不改动本机的「最近受控标签页」 |
| 把你电脑上的文件（如 `~/.ssh/id_rsa`）当素材传到平台上 | `upload` 只收配对服务器 `/api/ext/media/` 下的 URL，不收本机路径、不收字节 |
| 偷偷读你没交给它的文件夹，或读隐藏文件、私钥 | 本地文件夹要你自己选，并且每个任务再点一次头。路径不能含 `..`，只收文档类扩展名，点开头的文件和 `node_modules` 会跳过。文件字节只能上传到配对服务器的 `/api/ext/pull/`，不能指到别的网址 |
| 截到你正在看的页面 | 截图用调试器截指定的标签页；云端不能要求切前台，关了「高保真模式」时只有那一页本来就在前台才截得了 |
| 用钓鱼文案骗你 | `ask` 浮条的标题强制带上服务器域名；服务器给的所有文字在侧栏里都以纯文本显示 |
| 网页里的脚本冒充侧栏去批准任务、改配置 | 配对、批准、移除网站、解除这些操作只接受扩展自己的页面发来的消息（`sender.tab` 为空且 URL 是扩展页） |
| 让别人的浏览器替自己发帖（把自己的配对码骗你填） | 配对分两步，第二步之前侧栏会写明「交给账号『xxx』」，由你确认 |

### 身份与连接

- 配对确认时，扩展用 WebCrypto 生成 ECDSA P-256 密钥对，**私钥 `extractable:false`** 存在扩展的 IndexedDB，连扩展自己的代码也导不出来；服务器只收到公钥。
- 每次连接：服务器发随机数 → 扩展签 `vcorp-cloud-v1\n<服务器 origin>\n<设备号>\n<随机数>`。服务器上没有能冒充你浏览器的口令；签名带着 origin，拿到别的站点重放没用。
- 只连 `https://`（本机调试允许 `http://localhost`），走 WSS。
- 服务器侧：配对码 8 位、10 分钟、一次性，按 IP 限试错；每次运行一个临时 token，只在这次运行里有效，结束即作废并通知扩展关页；一个用户的命令只会送到这个用户自己配对的浏览器。

### 素材怎么进到网页

服务器把文件放在一个随机的能力 URL 后面（最长 2 小时）。扩展核对它确实指向配对服务器的素材接口后，在目标页面的内容脚本里直接取这个 URL、在内存里造 `File` 投进上传框，几百 MB 的视频也不落你的磁盘、不弹保存框。页面里取不到时，48MB 以内的文件改由扩展取了再转交。

### 本机那条路不受影响

本机 MCP 桥（`npx vcorp-chrome install`）的安全边界没有变：仍然只接受 `chrome-extension://` 来源和 token。云端通道是另一条独立的连接，两边的会话、标签页、标记互不干扰。
