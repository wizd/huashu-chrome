# 小脑：内置在扩展里的独立能力单元

> 状态：设计稿（2026-11-08），第一个按此实现的小脑是 `capture`（MSE 录制）。
> 现有的能力包（`loads/eda`、`loads/media`）就是小脑的前身，这份设计是在它们之上补齐"独立"所缺的部分，不另起一套。

## 为什么要小脑

云端 agent 不能在用户浏览器里跑任意 JS（没有 `eval`/`fetch`，见 `cloud-policy.js`）。
可有些事只能在页面里做：读播放器状态、在 `<video>` 上截帧、接住 MSE 收到的字节。
小脑就是把这类"页面里的固定动作"写成扩展自带的代码，云端只能**按名字点它、按白名单调 action、传 JSON 数据**。

不做动态加载：MV3 和商店政策都不允许远程代码，签名私钥也是新的风险点。
小脑随扩展发布；小脑要更新，就发扩展、通知用户升级。

## 独立性：四条边界

1. **一个小脑一个目录**：`loads/<name>/` 里有它的全部东西，删掉这个目录、重新构建，扩展照常工作。
2. **扩展核心不认识任何小脑**：`background.js`、`cloud.js`、`cloud-policy.js` 里不出现站点名、小脑名或小脑专属逻辑。
   它们只读 `load.json` 里的声明字段（hosts、actions、needs、outputs、limits）。现在 `media_pull` 的 YouTube Referer、`netHook` 这类特例往后都按声明走。
3. **小脑不碰 `chrome.*`**：小脑代码跑在页面（MAIN world），只能用宿主给的窄接口 `host`（下一节）。要权限就在 `load.json` 的 `needs` 里声明，由核心检查、执行。
4. **契约写在小脑里**：每个小脑的 `README.md` 写 action、payload、返回、错误码，是云端脚本（opus-video-maker 的 `media.mjs`、`relay.mjs` 等）唯一可依赖的东西。云端不读小脑的内部数据结构。

## 目录

```
loads/<name>/
  load.json      清单（下一节）
  entry.js       页面侧入口：注册 window.__vcorpLoads[name] = { version, ready(), call(action, payload) }
  early.js       可选：document_start 注入的钩子（needs 含 "early" 时才有）
  setup.js       可选：跑在入口之前，补页面缺的全局变量
  lib/           内部代码；站点适配器一站一个文件（lib/youtube.js…）
  test/          Node 测试：假页面 + 夹具，构建前必须过
  README.md      契约
```

构建仍由 `scripts/build-loads.mjs` 做：产物在 `extension/loads/<name>/`，入库，`extension/loads/index.js` 记清单和 sha256。

## load.json（v2）

在现有字段（name、title、description、version、hosts、waitFor、files、limits、actions、confirm、denied、vendor）之上新增：

| 字段 | 意思 | 核心怎么用 |
|---|---|---|
| `api` | 要求的宿主接口版本（整数，现为 `1`） | 构建时比对；扩展的 host 接口不够新就构建失败 |
| `hosts: "task"` | 不限死网站，只在本任务批准的网站上生效（通用小脑用，如 `capture`） | `loadHostAllowed` 改查任务的 sites |
| `needs` | 要用的宿主能力：`netHook`、`early`、`binaryOut` | cloud-policy 检查；`needs` 外的 host 方法在页面里不存在 |
| `outputs` | 二进制出口：`{ "<通道>": { "sniff": "media", "quota": "media" } }` | 页面交出的每段字节先过嗅探（现有 `mediaBody`），再记进任务额度（与 `media_pull` 共用 8GB），才开 pull 槽 |
| `minServer` | 云端脚本要求的最低小脑版本，写在 README 里同步 | 见「版本与升级通知」 |

`netHook: true` 并入 `needs: ["netHook"]`，旧字段构建时兼容。

## 宿主接口 `host`（api 1）

小脑入口拿到的唯一对象，按 `needs` 裁剪：

```js
host.emit(channel, bytes, meta)   // binaryOut：交出一段字节（ArrayBuffer），返回 { pullId, bytes } 或抛 NOT_MEDIA / QUOTA
host.session                      // 本标签页的会话存储：跨 call 保存状态（录到第几段、各轨格式）
host.progress(obj)                // 长任务进度：status 类 action 读得到，扩展侧栏也显示
host.early                        // early：读 early.js 记下的东西（只读快照）
```

传输：页面 → 隔离世界的 content script（`postMessage`，只认带一次性令牌的消息）→ service worker → 开 pull 槽。
字节不经过 JSON，不受 `payloadMax` 限制，只受 `outputs` 的嗅探和额度约束。

## early.js：页面加载前的钩子

录 MSE、记接口响应这类事，必须在页面脚本之前装好。规则：

- 只在小脑的 hosts（或任务批准的网站）上、**有任务武装了这个标签页时**注入。核心用 `registerContentScripts`（`world: "MAIN"`、`runAt: "document_start"`）注册，接着重载该标签页，脚本跑过就注销。
- 钩子默认什么都不留：只有当前文档被武装了才记数据；别的同站标签页即使在注册窗口里加载到了，也只是原样透传。
- 原调用永远照常执行，钩子出错不影响页面。

## 版本与升级通知

- 扩展的 `hello`/`status` 回报 `loads: { <name>: <version> }` 和 `hostApi`。
- 云端每个脚本写明它要的最低小脑版本（如 `capture >= 1.0.0`）。不满足时直接回 `EXT_OUTDATED`，信息里写"请把 vcorp-chrome 扩展升级到 x.y.z 以上"，不重试、不换路子。
- 网页端看到 `EXT_OUTDATED` 时在任务页和设备列表上显示升级提示；扩展侧栏在 `hello` 收到服务器要求的版本比自己高时也提示一次。
- 老扩展不认识的 action 会回 `LOAD_DENIED`：云端脚本按版本判断，把它也翻成 `EXT_OUTDATED`。

## 新增一个小脑的清单

1. `loads/<name>/` 写 `load.json`、`entry.js`、`README.md`、`test/`。
2. `npm run build:loads`，`npm test`（含通用契约测试：每个声明的 action 都有实现、needs 和用到的 host 方法一致、outputs 都有嗅探）。
3. 核心不用改。如果非改不可，说明缺的是宿主能力：给 `host` 加方法、`api` 加一，旧小脑不受影响。
4. 云端：在用到它的 skill 里按 README 调，写明最低版本。

## 第一个：`capture`（MSE 录制）

- `hosts: "task"`，`needs: ["early", "binaryOut"]`（标签页在后台时 status 报 `hidden`，由沙箱用 ask 请用户看一眼，不另设宿主能力），`outputs: { "media": { "sniff": "media", "quota": "media" } }`。
- `early.js` 包住 `MediaSource.prototype.addSourceBuffer` 和 `SourceBuffer.prototype.appendBuffer`：记每条轨的 MIME，复制每段字节；看到 `encrypted` 事件或 `MediaKeys` 就标 DRM，停止记录。
- action：`capture.start`（画质上限、倍速）、`capture.status`、`capture.pull`（轨道、序号范围 → pullId）、`capture.stop`（解除、恢复页面）。
- 站点适配器只管"锁画质、认广告、读视频 id 和时长"：`lib/youtube.js` 先做，其他站没有适配器时只用 `<video>` 的标准属性。
- 云端：opus-video-maker 的 `relay.mjs` 加 `capture` 子命令，取回各轨、按时间戳去重、ffmpeg 合成 mp4，再 `localfs.mjs put`。
