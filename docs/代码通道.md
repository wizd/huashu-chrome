# 代码通道：让模型写程序操作浏览器

2026-11-14 加入。动机见《浏览器操控的苦涩教训》：一步一个工具调用的「看→想→点」循环，
天花板是速度和成功率；模型的编程能力跨过临界点之后，把浏览器操作当成编程问题来解，效果有质的提升。

## 闭环

```
模型写一段 JS ──script──▶ MCP 进程里的 vm 执行
                            │  page.xxx() = 一条扩展命令（本机 WebSocket，几十毫秒）
                            ▼
                      用户的 Chrome（后台标签页，带登录态）
                            │
      结果 + 日志 + 每一步轨迹 ◀┘   失败时再加：出错行、卡在哪一步、页面现状、截图路径、
            │                       已经做过哪些写操作（别重做提交）
            ▼
   跑通了 → save → 站点函数库（~/.vcorp-chrome/sites/<域名>/<名>.js）
            │      只有成功跑过的代码才进库
            ▼
   下次 learnings(domain) 列出它 → script({run, args}) 一次调用
   失败 → 战绩记一笔（连续失败 = 站点改版）→ 模型读源码、改好、再 save 覆盖
```

三段缺一不可：**出**（代码能渗透进页面，包括 shadow DOM、iframe、ProseMirror），
**回**（不只说「失败了」，而是说清楚错在哪、页面现在什么样），
**存**（跑通的经验是能跑的程序，不是要重新理解的文字）。

## 文件

| 文件 | 作用 |
|---|---|
| `src/lib/page.js` | Playwright 风格的 `page` / `Locator`。页面里的部分是 `inPage()`，序列化后经扩展的 eval 注入 |
| `src/lib/script.js` | 执行器：vm 运行、跨调用的 `state`、后台任务、失败报告 |
| `src/lib/sites.js` | 站点函数库：出厂 `sites/` + 本机 `~/.vcorp-chrome/sites/`，战绩 `.stats.json` |
| `src/lib/upload.js` | 本机文件 → file input（CDP `DOM.setFileInputFiles`，大视频不经过桥） |
| `test/script.test.js` | 执行器逻辑（假桥） |
| `test/script-live.mjs` + `test/fixtures/script.html` | 真机实测：模拟发布页上跑完整流程 |

扩展侧**没有改动**：用的全是现有命令（eval、click、key、upload、navigate、network、screenshot、tabs、ask）。
eval 走 MAIN world，页面 CSP 拦下时扩展自动改走 CDP `Runtime.evaluate`。

## 和 Playwright 的差别

- 选择器默认穿透开放 shadow root、同源 iframe，以及站点自己挂出来的封闭 root（`el._sr`）。
- 不做严格模式：匹配多个时挑第一个可见的，轨迹里写明「匹配 N 个」。
- 可见性只看样式不看几何：后台标签页里 rect 不可靠。
- `fill` 填完读回核对，不一致直接抛 `FILL_MISMATCH`（字数上限、填错框都能当场发现）。
- `click` 先走扩展点击（有效果核对、无反应时升级为真实输入事件，约 2 秒）；元素在 shadow 里
  或扩展误报遮挡时，退回页面内完整事件序列（约 0.1 秒）。`click({js:true})` 直接走后者。
- `waitForResponse` 默认只认「上一次动作之后」的响应，所以先 click 再等不会漏。

## 实测（2026-11-14，本机 Chrome，后台标签页）

靶场上一整条发布流程（标题、正文分段、两个话题联想、文件、iframe 里的原创勾选、封闭 shadow 里的发布按钮、
等接口、等跳转）一次调用 **8.3 秒**跑完；存成站点函数后再调用 8.2 秒。其中两次扩展点击各约 2 秒，是主要耗时。

实测发现并修掉的：vm 上下文里的正则 `instanceof RegExp` 为假（跨 realm），`waitForURL(/re/)` 因此失败。

## 已知边界

- **云端通道不走这条路**。云端拿不到 eval（`extension/cloud-policy.js`），这是安全设计，不是遗漏。
  云端要用代码化的能力，路线是把站点函数做成能力包（`load`/`call`），或者在服务器侧的沙箱里跑
  同一套 `page` API、每个方法转成云端白名单命令。
- 跨源 iframe 进不去；封闭 shadow root 只有站点自己挂出来时才能进（否则要走 CDP `DOM.getDocument({pierce:true})`，未做）。
- vm 不是沙箱：脚本权限等同于 agent 已有的 shell。
- 三个平台（抖音、小红书、视频号）的站点函数还没写：要在真实账号上跑，发布是对外动作，需要用户点头。
