在这台电脑上启用桌面能力

启用后，配对的任务可以操作这台电脑上的应用（比如微信、Excel），每个应用都会先问你。全程大约 10 分钟，照着复制粘贴就行，不需要懂命令行。

  1. 1

    按键盘上的 ⊞ Win + R，在弹出的「运行」框里输入 cmd，按回车。会打开一个黑色窗口，下面的命令都粘贴到这里。

  2. 2

    看看装没装 Node.js

    桌面组件靠 Node.js 运行。粘贴下面这行，按回车：

    node -v

  3. 3

    安装 Node.js（只需一次）

    • 打开 nodejs.org 下载页，下载 LTS 版的 Windows 安装程序（.msi）。
    • 双击下载好的文件，一路点 Next。许可协议那页勾上「I accept」。所有选项保持默认。
    • 到 Tools for Native Modules 那页，不要勾那个框，用不上，勾了还要装很久。
    • 点 Install。Windows 问「你要允许此应用对你的设备进行更改吗」时点 是。最后点 Finish。

  4. 4

    安装桌面组件

    在黑色窗口里粘贴下面这行，按回车。第一次要下载 1～2 分钟，等它跑完、重新出现提示符。

    npx -y vcorp-chrome@latest desktop install
    C:\Windows\system32\cmd.exe—▢✕

  6. ✓

    怎么算成功

    侧栏显示 已启用 · desktop-…，后面没有「agent-desktop 用不了」，本页顶上的状态条变绿。这一页就可以关了。
  1. 1

    打开「终端」，看看装没装 Node.js

    按 ⌘ Command + 空格，输入 终端 或 Terminal，按回车。然后运行：

    node -v

    显示 v20 或更大的数字，跳到第 3 步；显示 command not found，做第 2 步。

  2. 2

    安装 Node.js（只需一次）

    从 nodejs.org 下载 LTS 版的 macOS 安装包（.pkg），双击后一路点「继续」。装完退出终端再重新打开，用 node -v 确认一下。
  3. 3

    安装桌面组件

    npx -y vcorp-chrome@latest desktop install
    Terminal
    ~ % npx -y vcorp-chrome@latest desktop install 已登记原生消息宿主 ai.vcorp.desktop（只允许扩展 … 调用） ✅ ~/Library/Application Support/Google/Chrome/NativeMessagingHosts 回到扩展侧栏点「启用桌面能力」。
    输出末尾的检查可能显示「agent-desktop 用不了」，那是从终端启动测的，先继续，最终以第 5 步侧栏的显示为准。
  4. 4

    回扩展侧栏点「启用桌面能力」

    侧栏 → 桌面应用 → 启用桌面能力 → 允许。第一次会重载扩展，侧栏关了就重新打开。

  5. 5

    给 Chrome 授权「辅助功能」

    打开 系统设置 → 隐私与安全性 → 辅助功能，点列表下方的 +，在「应用程序」里选 Google Chrome，打开它旁边的开关（列表里有 agent-desktop 的话也打开）。桌面组件由 Chrome 启动，macOS 把权限算在 Chrome 头上。

    然后回侧栏点 停用，再点一次 启用桌面能力：启用时才会重新检查权限。

常见问题

你看到的怎么办
「'npx' 不是内部或外部命令」或 'npx' is not recognized…（node 同理） Node.js 没装，或者黑色窗口是装之前开的。关掉窗口重新开（第 1 步）；还不行就重做第 3 步。
「在此系统上禁止运行脚本」 你用的是 PowerShell。按第 1 步改用「命令提示符」，或者把命令里的 npx 换成 npx.cmd。
Ok to proceed? (y) 输入 y 回车。（上面的命令带了 -y，正常不会问。）
卡很久不动，或报 ETIMEDOUT / ECONNRESET / network 从你的网络连 npm 太慢或连不上。换成国内镜像，再跑一次第 4 步：
npm config set registry https://registry.npmmirror.com
Specified native messaging host not found 第 4 步没做或没做成功。运行第 4 步的命令，再回侧栏点启用。
Access to the specified native messaging host is forbidden 桌面组件是旧版本。运行第 4 步的命令（一定要带 @latest）。
「Failed to start native messaging host」「Native host has exited」，或原来好好的突然不行了 升级过 Node.js，或者 npx 缓存被清理了。重新运行第 4 步的命令，再回侧栏启用。
「agent-desktop 用不了」（Windows） 常见原因有两个：
1. 缺少 Visual C++ 运行库（报错含 0xC0000135 或无输出）：从微软官网安装最新的 Microsoft Visual C++ Redistributable（常见电脑选 x64，ARM 电脑选 arm64）。
2. 智能应用控制或杀毒软件拦截（新装的 Windows 11 默认会拦没有签名的程序）：打开 Windows 安全中心 → 应用和浏览器控制 → 智能应用控制设置，选 关闭（较新的 Windows 更新后，关了以后还能再打开）；如果是杀毒软件把 agent-desktop 隔离了，把它恢复或加入信任。
处理完后重跑第 4 步，再回侧栏点停用、启用。
「没找到已安装的 Chrome / Edge / Chromium 配置目录」 （macOS / Linux）这台电脑上还没打开过浏览器。打开一次 Chrome，再跑一次安装命令。
「没有拿到权限，桌面能力保持关闭」 Chrome 询问权限时点了拒绝。再点一次「启用桌面能力」，选允许。
还是不行？在黑色窗口里运行 npx vcorp-chrome desktop status，把输出发给帮你的人。
