### 完全模式下云端多出的能力

- `shell`：默认用 PowerShell（输出 UTF-8），也可以选 pwsh / cmd / bash / sh。支持 `cwd`、`timeout`（最长 7 分钟，超时连同进程树一起杀掉）、`stdin`、`env`。
- `file`：stat / list / read / write / mkdir / delete / move / copy，路径不限。read 支持 `offset`/`length` 分段，单次最多 16MB；可以用 base64 读写二进制。
- `desktop`：agent-desktop 的全部命令，不需要申请应用，不挡浏览器窗口，允许 `--headed`、截图、剪贴板和通知；用 `argv` 可以把任意命令原样传给 agent-desktop。
- 大回包分页：超过 1MB 的回包先写进 `%TEMP%/vcorp-desktop-pages/`，扩展再用 `op: 'page'` 分段取回。

完全模式关闭时，行为和 2.1.0 完全一样。

## 二、第二阶段：安全方案（待定，讨论记录）

核心判断：**按 exe 名字开闸管的是入口，真正的风险在动作上**。一旦开放了 shell，应用名单、浏览器窗口闸这类限制就都拦不住什么了，所以新方案不应该回到逐个 exe 批准的老路。

主要威胁：
1. **提示注入**：云端 agent 读到的网页、应用内容里藏着指令，变成在用户电脑上执行的命令。
2. **服务器或账号被攻破**：所有开了完全模式的电脑一起沦陷。
3. **点到扩展自己的控件**：桌面侧能点 Chrome 主窗口里的侧栏「自动确认」、钱包和密码管理，扩展里的闸门就会被绕过。

候选方向：
- **设备级档位**（只能在本机设置）：观察（只读 + 截图）/ 协作（普通应用可写，终端只读，发送/删除要确认，付款拒绝）/ 完全（现状）。
- **所有档位都保留的底线**：不碰密码管理器；付款按钮必须用户亲手点；完全档以下不碰浏览器主窗口。
- **动作分级确认**：不可逆或对外的动作（删除、发送、改系统设置、写系统目录）弹通知等用户确认，而不是按应用名拦截。
- **可见、可停**：侧栏实时显示桌面上正在执行的命令（审计日志已经有了），提供一键暂停；完全模式开着时托盘或侧栏常驻提示。
- **按任务的范围**：任务开始时声明要用 shell 或文件，用户一次批准，批准只在这个任务内有效。
- **本地审计**：shell 的命令和输出写进 `~/.vcorp-chrome/audit.jsonl`，出了问题能查。
- **只读的系统探针 `sys`**（备选）：固定、参数有类型的查询（事件日志、崩溃、进程、服务、磁盘、更新），用于观察档下的系统体检，不需要开放 shell。
- 远期：桌面作为独立设备，用自己的密钥直连 maker（`desktop serve` 常驻进程），不再依赖浏览器中继，同时解决原生消息每次启动一个进程的开销。

## 三、为什么操作不了提权程序（UIPI）

现象：用户在 UAC 上点了「是」之后，HWiNFO64 就无法再操作了。

原因不在 agent-desktop，而是 Windows 的**用户界面权限隔离（UIPI）**：
- 点了 UAC 的程序运行在**高完整性级别**（管理员）。agent-desktop 由 Chrome 经原生宿主启动，和 Chrome 一样是**中完整性级别**。
- 低级别进程不能控制高级别窗口：SendInput 和 SendMessage 会被系统丢掉，UIA 的 Invoke 和 SetValue 会失败，读取树最多只能读到一部分。
- 所有不提权运行的自动化工具都受这个限制（AutoHotkey、Power Automate、pywinauto 都一样）。
- `shell` 也一样跑在普通权限下：读 Security 日志、改服务、写 `C:\Windows` 都做不到。
- UAC 弹窗本身显示在安全桌面上，任何用户进程都点不到，这是有意的设计，**只能由人来点**。

## 四、未来的高权限操作方案

### 方案 1：提权代理（推荐）

- 用户以管理员身份登记一次计划任务：用户登录时以「最高权限」启动一个常驻代理（`native-host/elevated.js`）。之后每次启动都不弹 UAC。
- 代理监听一个命名管道，ACL 只允许当前用户的 SID 连接；可以再加一个启动时生成、写在仅用户可读文件里的令牌。
- 原生宿主遇到以下情况时把命令转给代理：命令带 `elevated: true`，或者目标窗口属于提权进程（可以检查进程的完整性级别）。
- 代理以管理员身份运行 agent-desktop 和 shell，回包格式与现在一致。
- 开关同样只在本机：例如 `desktop full on --elevated` 或单独的 `desktop elevated install|uninstall`（登记或删除计划任务）。
- 代价：配对服务器上的任务在这台电脑上**等于管理员**。这一档必须和第二阶段的确认、可见、可停机制一起上线，不建议单独开放。

需要改的地方：新增 `native-host/elevated.js`；`src/cli.js` 加计划任务的登记和注销命令；`native-host/host.js` 加转发逻辑；`extension/cloud.js` 和 `desktop-policy.js` 透传 `elevated`；`SKILL.md` 补充用法；补测试（管道 ACL、未登记时的报错、转发路径）。

### 方案 2：uiAccess 签名程序

- 给 agent-desktop 的 exe 加 `uiAccess=true` 清单，签名后装到 `Program Files`，就能绕过 UIPI 控制提权窗口（屏幕键盘、讲述人就是这么做的）。
- 缺点：需要一张本机信任的代码签名证书（自签后导入受信任根也行）；每次升级 agent-desktop 都要重新签名；**只解决界面操作，shell 还是普通权限**。

### 方案 3：绕开界面，读数据

- 像 HWiNFO 这种只是要读传感器数据的场景，用它的共享内存或 CSV 日志，再用 `shell` / `file` 去读。比读界面快，也更准，而且不需要提权。

### 不建议

- 关闭 UAC，或者把 Chrome 整个以管理员身份运行：整台机器的所有程序都会默认拿到管理员权限。
